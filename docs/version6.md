# 第 6 版设计：连续报价 GRPO 与 MATD3 对比

V6 已在现有 V5 市场上新增 `grpo` 训练分支，保留 `matd3` 作为对照，通过场景的 `learning_config.algorithm` 选择。V5 的实现见 [version5.md](version5.md)。

核心原则：**主实验使用相同的市场任务和环境奖励，比较两种算法利用奖励学习报价的效果。** 奖励设计的变化放在补充实验中单独研究。

## 1. 与 V5 相同和不同的部分

| 项目 | V5：单智能体 MATD3 | V6：连续控制 GRPO 适配版 |
| --- | --- | --- |
| 市场与参与者 | 单节点 EOM、统一出清价，每小时一个产品；`example_02a` 中仅 `pp_6` 学习 | 相同 |
| 对手机组 | 使用已有固定规则报价，不更新模型 | 相同；固定规则不代表每小时价格必定相同 |
| 观测 | 16 维：12 小时历史出清价、2 维交付小时编码、上期本机出力、自身边际成本 | 相同，不增加负荷、未来电价或对手参数 |
| 动作的经济含义 | 两个连续报价价格，报量由机组参数及可用容量决定 | 相同 |
| 订单生成 | 动作乘价格基数后排序，低价用于最低出力段，高价用于灵活段 | 相同；两个动作维度不预先绑定报价段 |
| 环境奖励 | 利润减遗憾惩罚，再归一化 | 完全相同，包括系数、成本口径及特殊情况 |
| Actor 骨干 | `16 → 256 → 128`、ReLU | 相同 |
| 训练动作 | 确定性 Actor 输出加外部探索噪声，再裁剪 | 从 Actor 定义的概率分布采样，经有界变换得到动作 |
| 收益估计 | 双 Critic、目标网络及 TD 目标 | 无 Critic，使用采样轨迹的折扣回报和组内优势 |
| 数据利用 | 长期经验池，随机回放旧经验 | 当前旧策略采样一组轨迹，有限次更新后丢弃训练缓存 |
| 更新方式 | 更新双 Critic，延迟更新 Actor，软更新目标网络 | 使用动作概率比的裁剪目标更新 Actor |
| 验证与测试 | 确定性动作、按验证总奖励选模、独立测试 | 相同的评估规则；确定性动作取分布位置参数的变换 |

## 2. 奖励相同，训练信号不同

### 2.1 主实验复用 V5 的环境奖励

利润、遗憾惩罚及奖励分别为：

$$
\Pi_t=p_t^{clear}P_t^{acc}\Delta t-C_t^{variable}-C_t^{startup},
$$

$$
G_t=\lambda_t\max\left(0,(P_t^{avail}-P_t^{acc})(p_t^{clear}-c_t^{marginal})\Delta t\right),
$$

$$
\lambda_t=\begin{cases}
0.1,&P_t^{acc}>P_{\min},\\
0.5,&P_t^{acc}\le P_{\min},
\end{cases}
\qquad
r_t=\frac{\Pi_t-G_t}{100P^{rated}\Delta t}.
$$

沿用 [learning.py](../electricity_market_sim/deep_learning/learning.py) 的订单、成本和奖励计算：两段成交量先汇总，启动成本只计一次；无有效出清价，或因可用容量低于最低出力段而不能报价时，奖励为零。遗憾惩罚是人为奖励塑形，不是实际市场扣款。

价格与成本的归一化、动作映射使用相同的 `max_bid_price`，默认 100 EUR/MWh；奖励分母中的 100 是独立的固定奖励缩放参数。主实验均不改变。

### 2.2 算法对同一奖励做不同处理

MATD3 根据即时奖励和目标 Critic 构造 TD 目标；GRPO 从完整轨迹计算后续回报，再计算组内相对优势。**组内标准化属于训练过程，不替换环境奖励，也不改写结果 CSV 中的原始奖励。**

主实验折扣因子统一为 `gamma=0.99`。如研究“纯利润”奖励，应让两种算法分别重训，构成“算法 × 奖励”的补充实验；不同奖励定义下的数值不能直接比较，经济效果统一看实际利润和成交量。

## 3. 随机 Actor 与动作概率

GRPO 需要动作概率，不能直接复用 V5 的确定性 Actor 加任意外部噪声。建议使用二维对角高斯潜变量：

$$
z_t\sim\mathcal N\left(\mu_\theta(s_t),\operatorname{diag}(\sigma_\theta^2)\right),
\qquad a_{t,d}=f(z_{t,d})=\frac{z_{t,d}}{1+|z_{t,d}|}.
$$

Actor 的均值头为 `128 → 2`，另设两个可学习、与状态无关的 `log_std` 参数。隐藏层结构与 V5 一致；标准差设置上下界，训练探索由该分布承担，不再叠加 V5 的外部探索噪声或线性噪声日程。

Softsign 将动作映射到 `(-1,1)`，报价仍进入原有订单生成流程。计算概率时必须包含变换的雅可比：

$$
\log\pi_\theta(a_t|s_t)
=\sum_{d=1}^{2}\left[\log\mathcal N(z_{t,d};\mu_{\theta,d}(s_t),\sigma_{\theta,d}^2)
+2\log(1+|z_{t,d}|)\right].
$$

缓存采样时的 `z`、未排序动作及二维联合 `old_log_prob`。只在生成市场订单时排序价格，训练概率始终对应原始采样顺序。不要在变换后再次裁剪或排序，再按原高斯计算概率；数值保护应保证用于训练的动作与实际执行动作一致。

验证和测试固定使用 `a=f(μθ(s))`，不采样。这是部署动作规则，不宣称它等于变换后随机动作的数学期望。

## 4. 组采样与优势估计

### 4.1 同一起点，多条完整市场轨迹

第一版取组大小 `G=12`。冻结当前 Actor 为 `π_old`，使用不同的动作采样随机种子，从相同初始条件分别运行 12 条完整训练轨迹，然后才允许更新策略。

CPU 训练默认使用 `sampling_workers: 4`：4 个进程并行采样，每个进程只用一个计算线程，进程池在一次独立训练内复用。主进程按原串行顺序预留各轨迹的随机数状态，按轨迹编号合并结果，收齐整组后才更新策略；进程完成顺序不影响采样或更新。工作进程只回传训练张量和回合指标。

将 `sampling_workers` 设为 1 可切回串行。该参数只控制 CPU 采样；GPU 模式仍走原有串行路径。短场景可能主要受进程启动开销影响。

组内保持相同的训练时段、外生需求、燃料价格、可用率、对手规则和机组初始运行状态；历史电价窗口和上期出力按 V5 规则初始化。若环境增加随机外生扰动，组内共享扰动序列，动作采样使用独立随机流。

**只要求起点和外生条件相同，不要求后续观测相同。** 不同报价会导致不同成交、出清价及后续观测，这属于策略与市场的正常交互。不能把来自不同初始日期或不同策略版本的轨迹混成同一比较组。

使用 [simulate_learning_episode](../electricity_market_sim/simulation.py) 重复运行回合；采样时用 `functools.partial` 绑定输入目录、场景和数据时段。首版使用完整训练时段，不新增每小时市场快照分叉，也不把小时即时奖励比较当作长期收益比较。

学习会话维护前补 0 的 12 小时价格窗口，每次交付反馈只追加一次价格；上期出力直接取待完成步骤的结果，不保留完整市场历史。动作在进入会话时统一校验和按需裁剪。没有储能时直接跳过储能状态推算。这些处理由 MATD3 和 GRPO 共用，观测、出清与奖励保持一致。

### 4.2 逐时折扣回报与组内优势

对第 `i` 条轨迹，从末尾向前计算：

$$
R_{i,t}=r_{i,t}+\gamma(1-d_{i,t})R_{i,t+1},
\qquad R_{i,T}=0.
$$

在同一组、同一交付小时内构造：

$$
A_{i,t}=\frac{R_{i,t}-\overline R_t}{\max(s_t^R,\delta)},
\qquad
\overline R_t=\frac1G\sum_{j=1}^{G}R_{j,t},
\qquad
s_t^R=\sqrt{\frac1G\sum_{j=1}^{G}(R_{j,t}-\overline R_t)^2}.
$$

这里的 `s_t^R` 表示组内回报标准差，与观测 `s_t` 区分。优势在采样结束后计算并固定，同一批数据的各次更新不重新估计优势。

本设计是 GRPO 的项目适配：后续状态已经分化，基线按交付时间构造，不是同一状态下的精确价值函数；逐时回报归一化也不同于原论文将整段结果奖励分配给全部动作的方式。它保留组内比较、无价值网络和裁剪更新的思路，但存在采样方差、组归一化偏差与时段权重变化，不应宣称与 MATD3 的训练目标严格等价。

组内标准差低于设定阈值时，该时点不产生策略梯度，并记录占比，避免放大微小数值差异。无法报价的时点不参加动作损失，但其奖励和时间步仍保留在回报递推及交互计数中；应按“是否可以提交非零报价”判断，不能把可以报价但未成交的动作屏蔽掉。

## 5. 裁剪更新与采样缓存

对已采集的观测和原始动作计算概率比：

$$
\rho_{i,t}(\theta)=\exp\left(\log\pi_\theta(a_{i,t}|s_{i,t})-\log\pi_{old}(a_{i,t}|s_{i,t})\right).
$$

Actor 最大化以下代理目标，对有效位置等权平均：

$$
J(\theta)=\operatorname{mean}_{i,t}\left[
\min\left(\rho_{i,t}A_{i,t},
\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)A_{i,t}\right)
\right].
$$

第一版不设置固定参考策略 KL 惩罚，属于该惩罚系数为零的变体；通过概率比裁剪和相对旧策略的 KL 提前停止限制更新。监测采样观测上的 `KL(π_old || πθ)`；两者使用相同的可逆 Softsign 变换，可直接计算潜变量高斯分布间的解析 KL。

每遍更新按 minibatch 分批前向和反向传播，累积全部有效样本的均值梯度，统一裁剪后执行一次优化器更新；尾批按实际样本数加权。`minibatch_size` 控制计算批大小，每个 minibatch 不单独更新权重。这样首遍更新就使用全组有效样本，避免少量 minibatch 更新后停止而遗漏大部分数据。

每遍更新后重新计算整组有效样本上的 KL；超过 `target_kl` 则停止后续遍数。该阈值用于停止下一遍，不保证已执行更新的 KL 严格低于阈值，也不强制跑满 `update_epochs`。学习率从 `1e-4` 按实际训练组数作余弦衰减，末组为初始值的 `min_lr_ratio`（默认 0.25）；单组训练使用初始学习率。权重衰减和梯度裁剪分别由 `weight_decay`、`max_grad_norm` 配置。

每次更新的顺序固定为：冻结旧策略 → 完成组采样 → 计算并冻结回报/优势 → 有限遍数整组梯度更新及 KL 检查 → 清空训练缓存 → 重新采样。没有长期经验回放、双 Critic、TD 目标、策略延迟或软更新目标网络。

以下参数已在 [config/grpo.yaml](../electricity_market_sim/config/grpo.yaml) 中配置，场景可覆盖；这些是调参起点，不代表最优参数：

| 参数 | 建议起点 |
| --- | --- |
| 组大小 | 12 |
| CPU 采样进程数 | 4，每个进程单线程；1 为串行 |
| 折扣因子 | 0.99，与 MATD3 相同 |
| Actor 初始学习率 | `1e-4` |
| 末组学习率比例 | `min_lr_ratio=0.25`，按组余弦衰减 |
| 同批数据更新遍数 | 最多 4，每遍执行一次整组梯度更新 |
| minibatch | 256，用于分批累积梯度 |
| 概率比裁剪范围 | `[0.8, 1.2]` |
| KL 提前停止阈值 | 0.02 |
| 梯度范数上限 | `max_grad_norm=1.0` |
| AdamW 权重衰减 | `weight_decay=0.01`，显式保留原默认值 |
| 潜变量初始标准差 | 0.2；不等于报价空间固定 20 EUR/MWh 的标准差 |

不直接搬用 MATD3 的前 5 轮经验收集：GRPO 不需要填满回放池。若引入按边际成本预训练或其他策略初始化，两种算法都应获得相同的初始化机会，单独记录其预算，避免只给一方额外先验。

## 6. 公平对比与结果解释

沿用 `example_02a/base` 的交付时间划分：训练 `[2019-01-01, 2019-09-01)`、验证 `[2019-09-01, 2019-11-01)`、测试 `[2019-11-01, 2020-01-01)`。各时段独立初始化，维持 V5 的信息时界，不跨边界读取未来真实数据。

比较对象为边际成本基线、MATD3、GRPO。两种学习算法使用相同观测、动作价格范围、奖励、折扣因子、市场规则及选模指标，分别调参；相同网络骨干不意味着必须使用相同学习率或更新次数。

**训练预算按小时市场交互次数统一，不能直接按 episode 或组数统一。** 训练段长 `T=5832` 小时，MATD3 一轮计 `T` 次交互，GRPO 一个 12 轨迹组计 `12T=69984` 次。初始经验收集、全部组采样及任何额外仿真都要计入；组只在完整采集后更新，公共预算取可对齐的整组边界。

验证在相近的累计交互预算节点进行，单独报告验证开销和总耗时；调参候选数及预算也应相近。保留“按验证总奖励选择 best.pt”的规则，测试只在方案确定后运行，不依据测试成绩选算法参数或种子。

建议使用相同的 5 个运行种子，分别记录动作采样子种子，报告所有运行及其均值、标准差。种子相同不代表不同算法能获得完全相同的随机动作。

| 结果 | 目的 |
| --- | --- |
| 测试总利润、成交电量 | 判断实际经济效果 |
| 测试总奖励、平均小时奖励 | 判断共同训练任务上的表现 |
| 两段平均报价及成交比例 | 解释策略行为 |
| 验证成绩随市场交互次数的曲线 | 比较样本效率 |
| 验证成绩随耗时的曲线 | 比较实际计算成本 |
| GRPO 的 KL、裁剪比例、策略标准差、低方差组占比 | 诊断训练是否停滞或更新过大 |

不能因为 GRPO 删除 Critic 就断言总训练更快，也不能因为奖励更高就断言利润更高。完整回合采样可能使 GRPO 在相同交互预算下只有较少更新机会，这是需要如实展示的算法代价。

## 7. 实现分工与验收重点

| 位置 | 实现 |
| --- | --- |
| `deep_learning/learning.py` 与市场模块 | 复用观测、报价、出清和奖励语义 |
| [grpo_agent.py](../electricity_market_sim/deep_learning/grpo_agent.py) | 随机 Actor、串并行组采样、随机流分配、回报/优势计算、裁剪更新 |
| [grpo_training.py](../electricity_market_sim/deep_learning/grpo_training.py) | 从头按完整组训练，按配置的组间隔验证选模 |
| 学习配置与入口 | 支持 `matd3` / `grpo` 分支，按算法校验参数，不能仅修改算法名字就共用原训练循环 |
| 评估及指标模块 | 复用确定性策略评估、边际成本基线和经济指标；GRPO 诊断另存 |
| [checkpoints.py](../electricity_market_sim/deep_learning/checkpoints.py) 与输出目录 | 保存策略权重、算法名、分布和优势版本、数据时段；按算法隔离 |

MATD3 和 GRPO 每次都从头训练，只保存验证奖励最高的 `best.pt`，供后续评估和独立测试；不保存优化器、经验池或随机状态，不支持断点续训。`--checkpoint` 仅用于评估和测试，两种算法的模型不能直接互换。

从头训练不读取旧运行清单，训练完成后写出本次运行清单，同名模型和结果文件会被覆盖。独立测试读取清单并核对算法和数据时段。检查点的 `advantage_version` 仅记录训练方法，不限制策略评估；观测和动作分布版本仍需匹配。

实现后重点验证：动作变换和联合概率正确；概率比在新旧策略相同时为 1；旧策略在组采样期间不变；组起点一致且采样流独立；回报正确处理终止；常量回报不产生异常梯度；报价排序不改变训练动作；验证/测试不更新模型。原 MATD3 路径需执行仓库规定的单元测试及改动前后场景回归对比。

首版以完整训练回合建立对照。后续若尝试 168 小时窗口，需要明确状态初始化、窗口终止与尾部回报的处理，并同时训练相同窗口规则下的 MATD3 对照；窗口截断改变训练任务，不能将其影响全部归因于算法替换。

## 8. 运行与输出

在项目根目录、`ee_trade` conda 环境中运行。新增场景与原场景共用输入 CSV，输出按场景区分：

| 场景 | 算法 | 场景配置的默认训练预算 |
| --- | --- | --- |
| `base` / `tiny` | MATD3 | 保留原配置的训练轮数 |
| `grpo_base` | GRPO | 2099520 次交互，360 条轨迹、30 个组 |
| `grpo_tiny` | GRPO | 1728 次交互，24 条轨迹、2 个组，仅验证流程 |

短流程训练与独立测试：

训练脚本 `./scripts/grpo_train.ps1` 使用 PowerShell 原生参数，顶部的 `$Scenario = "grpo_base"` 和 `$Rounds = 60` 设置默认场景及策略迭代轮数。命令行用 `./scripts/grpo_train.ps1 -Rounds 60 --training-runs 1` 指定轮数。每轮是一组完整轨迹，入口根据实际场景的组大小和训练时段自动换算步数；`grpo_base` 的 60 轮对应 4199040 次交互。

脚本自动使用 `ee_trade` 环境并透传其余训练参数。短流程运行 `./scripts/grpo_train.ps1 grpo_tiny -Rounds 2 --training-runs 1 --no-plots`。按步数训练可直接使用 Python 入口的 `--training-steps`。下面是等价的直接命令及独立测试命令：

```powershell
conda activate ee_trade
python -m electricity_market_sim.main --input-dir examples/input/example_02a --scenario grpo_tiny --output-dir outputs/example_02a/grpo_tiny --training-runs 1 --no-plots
python -m electricity_market_sim.main --input-dir examples/input/example_02a --scenario grpo_tiny --output-dir outputs/example_02a/grpo_tiny --learning-mode test --no-plots
```

`--training-rounds` 表示每次独立运行的 GRPO 组数，也可直接传给 Python 入口；不传轮数或步数时，Python 入口沿用上表中的场景预算。`--training-steps` 表示每次独立运行的目标总交互数；GRPO 必须为完整组交互数的正整数倍。GRPO 不接受 `--training-episodes`。MATD3 可使用步数或轮数预算，不能同时指定。当前入口默认 1 次独立运行；正式对比建议显式设置 `--training-runs 5`。

等预算对比可分别对 `base`、`grpo_base` 设置 `--training-steps 2099520 --training-runs 5`，输出目录分开。不能直接把默认 30 轮的 MATD3 与默认 360 条轨迹的 GRPO 当作等预算实验。

`electricity_market_sim/config/grpo.yaml` 中的 `validation_groups_interval` 控制每隔多少个 GRPO 组（训练轮次）验证一次，必须为正整数，默认值为 5；场景的 `learning_config` 可覆盖。最后一组始终验证，设为 1 即每组验证。训练结束后仍使用最佳模型进行验证期策略与基线对比。

GRPO 输出学习指标、`best.pt` 和 `runs.json`。

一次优化器更新对应一遍完整有效数据；达到遍数上限或整组 KL 超限时停止更新，无有效样本时跳过更新。奖励、回报和优势定义保持不变。

多次运行时各次学习指标保存在各自的 `runs/run_XX/` 下，每次训练重新写出记录。GRPO 模型文件版本为 3，MATD3 为版本 2，两种算法均只保存最佳策略模型。
